# RCA — Pine Labs checkout "Payment initiation failed" (adityaretail.com)

## Problem statement
Live checkout shows "Payment initiation failed: Pine Labs payment is temporarily unavailable. The API credentials need to be refreshed." on Pay. Asked to confirm from production RUNTIME logs: (1) token URL the prod runtime used, (2) Pine Labs HTTP status + body, (3) token step vs order-creation step; plus raw state of PINE_LABS_ENVIRONMENT / PINE_LABS_API_URL / PINE_LABS_CLIENT_ID and whether they are quoted.

## Runtime evidence (production backend logs)
Deployment `email-audit-panel`, all recent runs share the SAME image (sha256:6d3795…85f9602 — the fixed source has NOT been redeployed yet). The only captured payment attempt is on run **f5222a70-da39-4c12-b8c8-3d6a4f1aa199** (created 2026-10-16 11:42:27Z, completed 11:46:06Z). Exact lines from `pine_labs_routes`:

No `[Pine Labs] POST .../orders` line and no `[Pine Labs] Response Status` line appear — order creation was never reached.

## Answers to the specific questions
1. **Token URL the prod runtime requested:** `https://api.pluralpay.in/api/auth/v1/token` — the **PRODUCTION** base. It did NOT use the UAT base `https://pluraluat.v2.pinepg.in/api`. A `pinepg`/UAT filter across every recent run returned zero hits. **The UAT-fallback suspicion is DISPROVEN by runtime evidence** — the environment resolved to PRODUCTION even on the old deployed code.
2. **HTTP status / body from Pine Labs:** `401` — body `{"status":401,"type":"","message":"You are not authenticated to perform the requested action.","traceId":"80acdf0d-c945-4827-a617-1bb8ee96d134"}`.
3. **Which step fails:** the **TOKEN / auth step** (`POST /auth/v1/token`). Order creation never ran.

## Environment variable state (ACTIVE run d05492cd — current live secrets)
- `PINE_LABS_ENVIRONMENT`: present, non-empty, **matches `PRODUCTION` exactly (unquoted — NOT wrapped in literal double quotes).**
- `PINE_LABS_API_URL`: present, non-empty, **matches `https://api.pluralpay.in/api` exactly (unquoted).**
- `PINE_LABS_CLIENT_ID`: present, non-empty. **VALUE/first-8-chars and quote-wrapping CANNOT be verified** — list_secrets never returns secret values, and I had no expected value to compare against.
- `PINE_LABS_CLIENT_SECRET`, `PINE_LABS_MERCHANT_ID`: present, non-empty (values not verifiable).

Note: secret values here are from the current ACTIVE run. The 401 was captured on run f5222a70; credential values on that earlier run are UNVERIFIED (cannot read a non-active run's secrets). But because the token URL was already PRODUCTION in that run, the ENVIRONMENT value was clearly resolving correctly there too.

## Root cause
The production runtime reached the **correct PRODUCTION token endpoint** and Pine Labs rejected it with **HTTP 401 "You are not authenticated to perform the requested action."** This is a **credential rejection at the auth/token step**, not a URL/UAT-base problem and not the quote-match code bug (ENVIRONMENT was already unquoted `PRODUCTION` and the request went to the production base).

Since the user confirms the same credentials return 200 from their terminal against the same URL, the credentials presented by the production pod differ from the working ones — most likely the production `PINE_LABS_CLIENT_ID` / `PINE_LABS_CLIENT_SECRET` (and/or `PINE_LABS_MERCHANT_ID`) are stale, wrong, or carry quotes/whitespace. These are user-owned Secrets.

## Important correction for the handoff
Redeploying the fixed source (the PINE_LABS_ENVIRONMENT exact-match / PINE_LABS_API_URL handling) will **NOT** resolve this symptom — the runtime already hit the production URL and still got 401. The blocker is the credential rejection at the token step.

## Suggested fixes
1. **User (Secrets):** In Deployment Panel → Secrets, re-enter `PINE_LABS_CLIENT_ID`, `PINE_LABS_CLIENT_SECRET`, and `PINE_LABS_MERCHANT_ID` to exactly match the credentials that return 200 from the terminal against `https://api.pluralpay.in/api/auth/v1/token`. Ensure NO surrounding double-quotes and NO leading/trailing whitespace. Save and redeploy.
2. **User (test & verify):** After the redeploy, retry checkout on the live site and re-pull runtime logs — expect `[Pine Labs Auth] Status: 200` followed by `[Pine Labs] POST .../orders`.
3. **Code (optional, not the fix):** The source env-matching fix can still ship, but on its own it does not address the 401.
