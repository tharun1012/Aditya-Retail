## Root cause
`frontend/src/components/LeadManagement.js` line 69 contains a stray directive:
```js
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [storeMode]);
```
ESLint is asked to disable the rule `react-hooks/exhaustive-deps`, but that rule is **not defined** in this project's resolved ESLint config. Verified in the eph sandbox against the failed run's source:
- `package.json` has **no `eslintConfig` block**.
- **No `eslint-plugin-react-hooks`** in `dependencies` or `devDependencies`.
- This is the **only** occurrence of the directive in `frontend/src` (grep confirmed exactly 1 file).

When an `eslint-disable` comment targets a rule no loaded plugin defines, ESLint raises a hard **error** ("Definition for rule '…' was not found"). CRA's production `yarn build` fails to compile on that error, exiting non-zero and failing Cloud Build step #8. (This is an ESLint *error*, not a warning, so `CI=false` would NOT suppress it.)

## Fix (E1 to apply in the source repo)
**File:** `frontend/src/components/LeadManagement.js`
**Change:** delete the single line at ~line 69:
```js
    // eslint-disable-next-line react-hooks/exhaustive-deps
```
Since `eslint-plugin-react-hooks` is not loaded, the rule cannot fire, so removing the disable directive introduces no new warning/error — it simply removes the reference to the undefined rule.

Optional alternative (if the exhaustive-deps lint is actually wanted): add `eslint-plugin-react-hooks` as a devDependency and an `eslintConfig` extending `react-app`. The minimal, lowest-risk fix is the one-line deletion above.
